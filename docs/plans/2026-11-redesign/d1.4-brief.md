# D1.4 brief: OpenF1 read-through store

Written 2026-11-14 by an Opus planner against `dev` @ `2942e20`; accepted by the coordinator. Implementation: D1.4a (storage layer), then D1.4b (read-through wiring). Nothing here touches `store.py`, `store_queue.py` or `store_types.py`.

## 1. Reuse

- **OpenF1 client** `backend/app/data/openf1/client.py` `get_json`: 404 → `[]`; 429 retried after OpenF1's advertised wait (3 attempts, ≤ 10 s each); 401 raises `OpenF1LiveLockoutError` (subclass of `OpenF1UnavailableError`); every request goes through the process-wide `PACER` (`RequestPacer`, 0.4 s gap, `OPENF1_MIN_REQUEST_GAP_SECONDS`). The read-through goes inside `get_json`. **No new pacer**, and don't reuse D1.5's Jolpica `Pacer` (it models Jolpica's 4/s + 500/h; OpenF1's limit is a burst 429 that `get_json` already honours).
- **Finished sessions** `backend/app/data/openf1/sessions.py`: `session_ended()` (`date_end` + `ANALYSIS_SESSION_SETTLE_MINUTES` = 60); `weekend_sessions()` (every reader goes through it via `find_session`; the one place `(year, round)` is known); `weekend_schedule()` (f1db's session list, D1.3, no OpenF1 request); `OpenF1Session`.
- **Own-table Postgres pattern** `backend/app/data/analysis_cache.py`: `_SCHEMA_SQL` with `IF NOT EXISTS` + RLS; `psycopg.connect(dsn, autocommit=True)` per call, imported lazily; `_schema_ready` flag; a DB failure is a logged miss, never an error. P0c (`feat/oracle-backend`) keeps this driver, no pool, and adds a module-level `ensure_schema(conn)` per table module registered in `scripts/ensure_schema.py` `SCHEMAS`: copy that convention.
- **File fallback:** `FileDocumentStore` in `store.py` writes atomically (temp file + `os.replace`). Read it, don't import it; the store needs its own small file backend (lap-sized data doesn't belong in `app_documents`).
- **Test helpers:** `tests/openf1_support.py` (`FakeOpenF1`, `serve(monkeypatch, module, routes)`, `NO_RESULTS`); `tests/calendar_support.py` (`meetings_2026()`, `calendar_f1db` fixture); the `FakeConnection` shape in `tests/test_analysis_cache.py:23-50`; the real 401 body at `tests/test_openf1_client.py:62`; `monkeypatch.setattr(client.PACER, "wait", ...)` as at `test_openf1_client.py:210`.
- **Real fixtures:** `tests/fixtures/mexico_2026_r19/` (race 11404: `openf1_sessions.json`, `openf1_drivers.json`, `openf1_session_result.json`, `openf1_pit.json` 67 rows with **every `stop_duration` empty**, `openf1_stints.json` 80 rows merging to 72 = **real pit-lane-pass splits**); `sao_paulo_2026_r20/openf1_sessions.json` (race 11412); `sao_paulo_2025_r21/openf1_sessions.json` + `openf1_race_control.json` (race 9869, `CAR 12 (ANT) TIME 1:16.547 DELETED … LAP 6`).
- **Quirk handlers (reuse, don't reimplement):** `openf1_stints.laps_in_progress`, `red_flag_moments`, `stints_from_openf1` (`_merge_same_set`); `openf1/race_control.standing_deletions` + `deleted_laps` (match by time); `openf1/laps.laps_from_openf1`; `pit_sheet._openf1_stationary` (skips empty `stop_duration`).
- **Readers to switch: none.** `race_classification`, `pit_sheet`, `openf1_stints`, `standings_rounds`, `openf1_qualifying`, `edition_sources`, `session_laps`, `race_context`, `entry_list`/`session_entries` all call `get_json(client, <endpoint>, {"session_key": k})` for sessions from `weekend_sessions`, so they read through with no change. D1.4 changes only `client.get_json` and `sessions.weekend_sessions`.

## 3. Layout (decided)

Two tables; each stored entry is one whole OpenF1 answer as a JSONB array plus typed key and provenance columns. Rows come back verbatim (quirks included); one statement stores a whole answer or nothing; arrays > 2 KB are TOAST-compressed (per-row JSONB would be ~3× larger under Supabase's 500 MB cap). The `openf1_` prefix leaves generic names for D2.3. Plan names → endpoints: `entries`=`drivers`, `classifications`=`session_result`, `pit_stops`=`pit`, `race_control_messages`=`race_control`, `weather_observations`=`weather`.

```sql
CREATE TABLE IF NOT EXISTS openf1_sessions (
    session_key INTEGER PRIMARY KEY, year SMALLINT NOT NULL, round SMALLINT NOT NULL,
    meeting_key INTEGER NOT NULL, circuit_key INTEGER, code TEXT NOT NULL, name TEXT NOT NULL,
    date_start TIMESTAMPTZ, date_end TIMESTAMPTZ NOT NULL,
    source TEXT NOT NULL, fetched_at TIMESTAMPTZ NOT NULL);
CREATE INDEX IF NOT EXISTS openf1_sessions_round ON openf1_sessions (year, round);
CREATE TABLE IF NOT EXISTS openf1_rows (
    endpoint TEXT NOT NULL, session_key INTEGER NOT NULL, payload JSONB NOT NULL,
    source TEXT NOT NULL, fetched_at TIMESTAMPTZ NOT NULL, provisional BOOLEAN NOT NULL,
    PRIMARY KEY (endpoint, session_key));
ALTER TABLE openf1_sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE openf1_rows ENABLE ROW LEVEL SECURITY;
```

No foreign key (P0c's data-only `pg_dump` would have to order tables). No migration framework: each store creates its tables on first use (`_ensure_schema` + flag) and exposes module-level `ensure_schema(conn)`. Tests: conftest clears `DATABASE_URL`, so the file backend runs; Postgres is tested through a faked `psycopg.connect`. Empty `DATABASE_URL` → file backend at `OPENF1_STORE_DIR`.

## 4. D1.4a files

- **New `backend/app/data/openf1/session_store.py`** (~180 lines; imports only stdlib, `structlog`, `app.config`; never `client`/`sessions`):
  - `STORED_ENDPOINTS = frozenset({"drivers","session_result","laps","pit","stints","race_control","weather","team_radio"})` (comment: `position`, `intervals`, `overtakes` held back until the Oracle VM); `SOURCE = "openf1"`; `SESSION_FIELDS` = `OpenF1Session`'s field names.
  - `@dataclass(frozen=True) class KeptRows: rows: list[dict]; fetched_at: datetime; provisional: bool` with `fresh(self, now) -> bool` (not provisional, or `now - fetched_at < OPENF1_STORE_PROVISIONAL_TTL_MINUTES`).
  - `Lookup = tuple[datetime | None, KeptRows | None]` (the session's `date_end` if registered, the kept rows).
  - `FileSessionStore(root: Path)` and `PostgresSessionStore(dsn: str)`, each with `lookup(endpoint, session_key) -> Lookup`, `save_rows(endpoint, session_key, kept: KeptRows)`, `weekend(year, round_num) -> list[dict]` (`SESSION_FIELDS` only), `save_sessions(year, round_num, records: list[dict])`. (Ruff `max-args` is 4, hence `KeptRows` as one argument.)
  - Files: `{root}/{session_key}/session.json` (record + `year`, `round`, `source`, `fetched_at` ISO); `{root}/{session_key}/{endpoint}.json` (`{source, fetched_at, provisional, rows}`); temp file + `os.replace`; `weekend()` globs `*/session.json` and filters. Endpoints come from the whitelist and keys are ints, so no path traversal.
  - Postgres: `lookup` is one round trip, `SELECT s.date_end, r.payload, r.fetched_at, r.provisional FROM openf1_sessions s LEFT JOIN openf1_rows r ON r.session_key = s.session_key AND r.endpoint = %s WHERE s.session_key = %s`; `save_rows` = `INSERT … ON CONFLICT (endpoint, session_key) DO UPDATE SET payload, source, fetched_at, provisional` with `Jsonb(rows)`; `save_sessions` = `executemany … ON CONFLICT (session_key) DO UPDATE`; `connect_timeout=5`; endpoints always as parameters (ruff `S608`).
  - `ensure_schema(conn)`; `_build(dsn)` → Postgres when set else `FileSessionStore(Path(OPENF1_STORE_DIR))`, constructors touch neither disk nor network; `STORE = _build(os.getenv("DATABASE_URL", "").strip())`; `now()` → UTC now.
  - Module-level `lookup`, `save_rows`, `weekend`, `save_sessions` call through to `STORE`, catch `Exception` (as `analysis_cache`; BLE001 ignored in `ruff.toml`) and log `openf1_store.read_failed` / `openf1_store.write_failed`. A failed lookup returns `(None, None)` ("fetch from OpenF1"). `save_sessions([])` does nothing.

## 5. D1.4b files

- **`client.py`:** rename today's `get_json` body to `_fetch(client, path, params)`, unchanged. New `get_json`, same signature:

```python
if path not in session_store.STORED_ENDPOINTS or set(params) != {"session_key"}:
    return _fetch(client, path, params)            # narrower queries and held-back endpoints pass through
session_key = int(params["session_key"])
date_end, kept = session_store.lookup(path, session_key)
if date_end is None:                               # not a finished, registered session: never stored
    return _fetch(client, path, params)
now = session_store.now()
if kept is not None and kept.fresh(now):
    return kept.rows
try:
    rows = _fetch(client, path, params)
except OpenF1UnavailableError:                     # 401/429/outage: a provisional copy beats "unavailable"
    if kept is None:
        raise
    return kept.rows
if not rows:                                       # an empty answer is never stored
    return kept.rows if kept else rows
final_at = date_end + timedelta(hours=OPENF1_STORE_FINAL_AFTER_HOURS)
session_store.save_rows(path, session_key, session_store.KeptRows(rows, now, provisional=now < final_at))
return rows
```

- **`sessions.py` `weekend_sessions`:** first `_kept_weekend(year, round_num)`: scheduled codes = `{s.code for s in weekend_schedule(...)}`; if non-empty and every code is kept, return the kept `OpenF1Session(**record)` in running order with no request (an empty schedule never counts as complete). Otherwise fetch as today, then `session_store.save_sessions(year, round_num, [asdict(s) for s in sessions if session_ended(s)])`. Factor the sort into `_running_order()`. Two `# shortcut:` comments: a weekend with a cancelled session f1db still lists is never complete (always fetched); inside a live weekend the list is fetched and gets the 401 (later: serve the kept sessions).
- **Semantics:** only a session past `date_end` + 60 min is registered; an unregistered session always passes through; a 401 raises before any save; a stored session or complete stored weekend serves with zero requests even during another session's live lockout; rows fetched within 24 h of the session end are provisional (post-race penalties landed hours later at R19), refreshed at most every 30 min, kept if a refresh fails or is empty.
- **Idempotency keys:** `openf1_sessions.session_key`; `openf1_rows (endpoint, session_key)`; files one path per key, replaced per write.
- **Partial fetch never complete:** one stored entry = one whole response in one upsert/`os.replace`; any fetch error raises before the save; unsettled sessions never registered; empty answers never stored; a reader failing midway keeps only endpoints it fully fetched (the next read fetches the rest); a weekend comes from the store only when every f1db-scheduled session is registered.

## 7. Risks and open points

1. **After P0c merges:** add `("openf1_sessions, openf1_rows", session_store.ensure_schema)` to `scripts/ensure_schema.py` `SCHEMAS`. P0c's migration copies only `F1AI_APP_TABLES` (`deploy/oracle/bin/lib.sh`), so the new tables start empty on the VM (they refill on demand). No health/backoff: during a DB outage each read pays one failed connect (≤ 5 s).
2. **Plan deviations (coordinator-accepted, flagged to the user):** two `openf1_*` tables instead of nine generic ones; provisional = fetched within 24 h of the session end, refreshed every 30 min; there is no OpenF1 GitHub Actions ingest to delete.
3. "Lap rows missing `date_start` (carry the leader over)": no code carries the leader over today; `laps_in_progress` puts an undated moment on lap 1. D1.4 proves undated rows survive the store; filling a missing start from the leader's lap would be new reader logic (D1.10).
4. Size/latency: laps stored twice (raw here, parsed in `analysis_cache`); ~0.5 MB compressed per weekend, ~12 MB a season (check Supabase usage before merging to main). On Supabase every stored-endpoint read adds a ~100–300 ms connect, even for sessions not stored yet.
5. Empty answers (no `team_radio`) are asked again on every read: deliberate (never cache failure as empty).
