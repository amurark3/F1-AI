## 2. Backend

### 2.1 Provenance on a tool result: `backend/app/api/tools/provenance.py` (new)

```python
@dataclass(frozen=True)
class ReachRow:
    key: str        # driver code, or the team's name
    name: str       # f1db's display name
    team: str       # the team (a team row: its own name)
    points: float
    max: float      # points + the most it can still score

@dataclass(frozen=True)
class ReachChart:
    title: str                                   # computed, §2.3
    championship: Literal["drivers", "constructors"]
    year: int
    rows: tuple[ReachRow, ...]
    kind: Literal["reach"] = "reach"

@dataclass(frozen=True)
class Provenance:
    sources: tuple[str, ...]
    subject: str | None = None
    chart: ReachChart | None = None

class Sourced(str):
    """A tool's text with its provenance attached; it reads as the plain text everywhere else."""
    provenance: Provenance
    def __new__(cls, text: str, provenance: Provenance) -> Self: ...
```

`Sourced` is a `str`, so every existing caller and test that reads a tool's text (`tool.invoke(args)`, the claim checker, the eval, `mcp_server.py`) is unchanged; checked in a probe: `@tool` hands the same object back from `invoke`. Only a tool's **success** returns become `Sourced`; failure and "nothing found" texts stay plain strings, so they carry no chip. Use `typing.Self` as the `__new__` return type (Ruff PYI034).

Chip helpers in the same module:

- `SOURCE_NAMES = {"f1db": "f1db", "fia-final-classification": "FIA final classification", "openf1-session-result": "OpenF1 session results", "jolpica-qualifying": "Jolpica qualifying"}`; an id not listed prints as sent.
- `chip(source, *details, version=None) -> str`: the name (plus `" {version}"` when given), then each truthy detail, joined by `" · "`. `chip("f1db", "standings after R19", version="v2026.19.0")` → `f1db v2026.19.0 · standings after R19`; `chip("openf1-session-result", "provisional")` → `OpenF1 session results · provisional`; `chip("OpenWeatherMap")` → `OpenWeatherMap`.
- `f1db_chip(*details)`: `chip("f1db", *details, version=installed_version())` (`app.data.f1db_source.installed_version`; `None` drops the version).
- `classification_chips(sources, *, final) -> tuple[str, ...]`: one chip per source dict of a session result (`{"source", "version"?, "document"?}`): the version (an `f1db` source without one gets `installed_version()`), `f"doc {document}"` when present, and `"provisional"` when not `final`. Examples: `f1db v2026.20.0`; `FIA final classification · doc 86`; `OpenF1 session results · provisional`.

### 2.3 Standings provenance and the reach chart: `backend/app/api/tools/standings_provenance.py` (new)

`standings_provenance(standings: CurrentStandings, reach: TableReach, championship: Literal["drivers", "constructors"]) -> Provenance`. The standings tools compute `reach = drivers_reach(standings)` (or `constructors_reach`) once, use it for `title_line` as today, and return `Sourced(text, standings_provenance(standings, reach, …))`.

- **Sources**, from `standings.sources` in order: `role == "base"` → `chip("f1db", f"standings after R{through_round}", version=source["version"])`; `role == "points"` → `chip(source["source"], f"R{round}", "provisional")`; `cross_check` rows are skipped. When a chart is drawn, append the basis chip `"{races} race(s){ + n sprint(s)} left · {points_on_offer} pts max"` (`pluralise` from `app.services.race_control_common`; no sprint part when 0), e.g. `4 races left · 100 pts max`.
- **The fight:** the first place `p` (1-based, in table order) such that some row below it can still pass it (`reach.can_pass(row.key, target.key)`); the chart rows are that place's row followed by every row below that can pass it, in table order. No chart when `reach.remaining is None` (no calendar) or no place has a chaser (season settled).
- **Rows:** `ReachRow(key, name, team, points, points + reach.points_on_offer)`.
- **Title** (whole caption, computed): `"{n} {drivers|teams} can still win the title"` when `p == 1`, else `"{n} {drivers|teams} can still finish {ordinal}"` (`first` … `tenth`, then `P{p}`), then `" · points after round {as_of_round} → most possible"`, then `" · provisional"` when `standings.provisional`. Mockup state (2026 after R19, 4 races, no sprints): `5 drivers can still finish second · points after round 19 → most possible`, rows Verstappen 261→361, Hamilton 259→359, Russell 250→350, Leclerc 245→345, Norris 221→321.

### 3.1 `parseChatStream(raw: string, done: boolean)`

Returns `{ content, toolStatus, data }` from the whole raw text received so far (the hook keeps the raw string and re-parses on each chunk, so a marker split across chunks is never lost):

- every complete marker (`/\[(TOOL_START|TOOL_END|ANSWER_DATA)\]([\s\S]*?)\[\/\1\]/g`) is removed from `content`;
- `toolStatus` = the body of the last `TOOL_START` with no later `TOOL_END`, else `null`;
- `data` = `toAnswerData(JSON.parse(body))` of the **last** `ANSWER_DATA`; bad JSON → `null`;
- while `!done`, a trailing unclosed marker (`[TOOL_START]…`, `[ANSWER_DATA]{…` or a bare `[TOOL_ST`-style prefix at the very end) is cut from `content`; once `done`, nothing more is cut. `content` is trimmed when `done`.

### 3.2 `useChat`

State: `chats`, `activeChatId`, `activeChat`, `messages`, `input`, `isLoading`, `toolStatus`, `failure: string | null`, `deleted: { chat: Chat; index: number } | null`; refs `messagesEndRef`, `inputRef`; actions `setInput`, `sendMessage`, `handleSubmit`, `handleNewChat`, `handleSelectChat`, `handleDeleteChat`, `undoDelete`, `regenerate`, `retry`. Kept as today: the per-browser `f1ai_user_id`, `thread_id` = chat id, render-time sync of messages on chat change, auto-scroll on new messages, focus back to the input when an answer completes, the input disabled while loading.

- The request sends `messages.map(({ role, content }) => ({ role, content }))`, never the stored `data`.
- On an OK response with a body: append `{ role: "assistant", content: "" }`, then on each chunk set the last message to `{ role: "assistant", content, ...(data && { data }) }` and `toolStatus`; at the end persist it with `updateLastMessage`.
- On a failure, nothing is appended or persisted: `failure` = `UNREACHABLE_REASON` (`@/app/ui/section/sectionState`) when `fetch` rejects, `` `The server answered ${status}.` `` for a non-OK response, `"No answer stream was received."` with no body. `failure` clears on the next send, on a new question and on selecting a chat.
- `retry()` re-sends the last user message: it drops that trailing user turn from `messages` first (as `regenerateLastMessage` does today), then calls `sendMessage`.
- `regenerate()` is today's `regenerateLastMessage`: no-op while loading or with fewer than two messages; drops the trailing assistant turn(s) and the last user turn, then re-sends that question. The old answer is not kept (the mockup's header comment). It also drops them from the stored thread (write the trimmed `messages` back before re-sending), so a reload never shows both.
- `handleDeleteChat(id)`: removes the thread at once (no confirm), keeps `deleted = { chat, index }`, and if it was the open thread clears `activeChatId` and `messages`. `undoDelete()` restores it at its index and clears `deleted`. `deleted` clears on the next delete (replaced), the next send and `handleNewChat`; it is not persisted, so a reload drops it.
