# Plan: Live Activity Lifecycle Manager (iOS)

**Phase:** 04 — Live Race Experience
**Task:** 04-02
**Requires:** 04-01

## Goal

Create `LiveActivityService.swift` — an `@Observable` class that starts, updates, and ends the `RaceLiveActivity` — then wire it into `LiveTab.swift` so the Dynamic Island starts when position data arrives over the WebSocket, updates on every position message, and ends 30 minutes after the session completes.

## Requirements Satisfied

- LIVE-01: Dynamic Island shows current driver position, gap to leader, current lap, and safety car status during active sessions
- LIVE-02: Dynamic Island compact and expanded views update in real-time from WebSocket timing data

## Context

**Service pattern:** Follow the existing `@Observable final class LiveTimingService` pattern. `LiveActivityService` is a separate service — do NOT put `Activity<RaceLiveActivityAttributes>` directly on `LiveTimingViewModel`. This avoids `ActivityKit` import confusion between targets.

**Start trigger:** Do NOT start the activity on calendar `status == "in_progress"` alone — that covers the whole weekend. Start it only after the WebSocket connects AND the first `positions` array arrives with data. This is `vm.positions.isEmpty == false` after `vm.isConnected == true`.

**Update trigger:** `onChange(of: vm.positions)` in `LiveTab.liveContent()`. Every WebSocket position update calls `Task { await liveActivityService.update(...) }`.

**End trigger:** When `LiveTab.onDisappear` fires (user leaves) OR when `vm.sessionStatus?.status` transitions to "finished"/"ended". Post-session: use `ActivityUIDismissalPolicy.after(Date().addingTimeInterval(30 * 60))` — 30-minute display then auto-dismiss.

**Tracked driver selection:** Read `UserDefaults.standard.string(forKey: "favoriteDriver") ?? ""`. If empty or not found in positions, fall back to `positions.first` (race leader). This key is set by 04-03 but the read logic belongs here.

**`RaceEvent` model:** Already exists at `ios/F1AI/Models/Race.swift`. `LiveActivityService.startActivity` accepts a `RaceEvent` for the static attributes (`raceName`, `round`, `year`). Extract `year` from `race.date?.prefix(4)` as `Int`.

**ActivityKit API (iOS 16.2+):** Use `Activity.request(attributes:content:)` with `ActivityContent(state:staleDate:)`. Set `staleDate: Date().addingTimeInterval(30)` so iOS grays out the display if data goes stale (app backgrounds).

**`LiveTimingViewModel`:** Add `commentaryEntries` in 04-04 — do NOT add it here. This plan only adds what `LiveActivityService` needs: no ViewModel changes required beyond wiring in `LiveTab`.

## Implementation Steps

### Step 1: Create LiveActivityService.swift

**File:** `ios/F1AI/Services/LiveActivityService.swift`
**Action:** create
**Changes:**
- `import ActivityKit`, `import Foundation`
- Declare `@Observable final class LiveActivityService`
- Private property: `private var currentActivity: Activity<RaceLiveActivityAttributes>?`
- Computed property: `var isActive: Bool { currentActivity != nil }`
- `func startActivity(race: RaceEvent, positions: [LivePosition], sessionStatus: SessionStatus?)`:
  - Guard `ActivityAuthorizationInfo().areActivitiesEnabled` — return silently if false
  - Guard `currentActivity == nil` — return if already running
  - Resolve tracked driver: `let fav = UserDefaults.standard.string(forKey: "favoriteDriver") ?? ""; let tracked = fav.isEmpty ? positions.first : (positions.first(where: { $0.driver == fav }) ?? positions.first)`
  - Build `ContentState`: `trackedDriver` from `tracked?.driver ?? ""`, `trackedPosition` from `tracked?.position ?? 1`, `trackedGap` from `tracked?.gap ?? "LEADER"`, `currentLap` from `sessionStatus?.lap ?? 0`, `totalLaps` from `sessionStatus?.totalLaps ?? 0`, `sessionStatus` string from `sessionStatus?.status ?? "started"`, `isLeader` from `tracked?.position == 1`
  - Build `RaceLiveActivityAttributes`: `raceName: race.name`, `round: race.round`, `year: Int(race.date?.prefix(4) ?? "2025") ?? 2025`
  - Call `currentActivity = try Activity.request(attributes: attributes, content: ActivityContent(state: initialState, staleDate: Date().addingTimeInterval(30)))` inside a `do/catch`; log error with `print("LiveActivity start failed: \(error)")` on failure
- `func update(positions: [LivePosition], sessionStatus: SessionStatus?) async`:
  - Guard `currentActivity != nil`
  - Resolve tracked driver same as start (re-read `UserDefaults` so mid-session favorite changes propagate)
  - Build updated `ContentState`
  - Call `await currentActivity?.update(ActivityContent(state: newState, staleDate: Date().addingTimeInterval(30)))`
- `func endActivity(positions: [LivePosition], sessionStatus: SessionStatus?) async`:
  - Build final `ContentState` from current positions
  - `let dismissal = ActivityUIDismissalPolicy.after(Date().addingTimeInterval(30 * 60))`
  - Call `await currentActivity?.end(ActivityContent(state: finalState, staleDate: nil), dismissalPolicy: dismissal)`
  - Set `currentActivity = nil`

### Step 2: Inject LiveActivityService into LiveTab and wire lifecycle

**File:** `ios/F1AI/Views/Tabs/LiveTab.swift`
**Action:** modify
**Changes:**
- Add `import ActivityKit` at the top
- Add `@State private var liveActivityService = LiveActivityService()` as a `@State` property on `LiveTab`
- In `liveContent(race: RaceEvent) -> some View`, update the existing `.onAppear` modifier:
  ```swift
  .onAppear {
      vm.connect(year: calendarVM.selectedYear, round: race.round)
      // Activity starts only after first positions arrive (handled by onChange below)
  }
  ```
- Add `.onChange(of: vm.positions)` modifier to the `VStack` returned by `liveContent()`:
  ```swift
  .onChange(of: vm.positions) {
      guard !vm.positions.isEmpty else { return }
      if !liveActivityService.isActive {
          liveActivityService.startActivity(
              race: race,
              positions: vm.positions,
              sessionStatus: vm.sessionStatus
          )
      } else {
          Task {
              await liveActivityService.update(
                  positions: vm.positions,
                  sessionStatus: vm.sessionStatus
              )
          }
      }
  }
  ```
- Update the existing `.onDisappear` modifier to also end the activity:
  ```swift
  .onDisappear {
      vm.disconnect()
      Task {
          await liveActivityService.endActivity(
              positions: vm.positions,
              sessionStatus: vm.sessionStatus
          )
      }
  }
  ```
- Add `.onChange(of: vm.sessionStatus?.status)` to detect session end and call `endActivity` when status becomes "finished" or "ended":
  ```swift
  .onChange(of: vm.sessionStatus?.status) { _, newStatus in
      guard let s = newStatus, s == "finished" || s == "ended" else { return }
      Task {
          await liveActivityService.endActivity(
              positions: vm.positions,
              sessionStatus: vm.sessionStatus
          )
      }
  }
  ```
