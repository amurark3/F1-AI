## 2. Shared decisions (all commits)

- **Loading:** no page awaits backend data.
  - `page.tsx` awaits only `params`. It renders `<Suspense fallback={<X seed={null} …/>}><SeededX …/></Suspense>`, one boundary per data section. The **fallback is the same client component, unseeded**: it shows its own skeleton and starts fetching in the browser.
  - The `Seeded*` async server components live in sibling `*Seed.tsx` files, never in `page.tsx`, because Next rejects extra page exports. Each one awaits `lib/server/profiles.ts` and passes `seed`.

## 11. Risks

1. **Merge hotspots** are the §8 files. `PageHero` is the likeliest real conflict if P5.2 extends it too.
2. **notFound inside Suspense:** an unknown id answers 200 + noindex rather than 404, because the stream has started. Prerendered ids are unaffected.
3. **Provisional table:** after a race, before f1db publishes, hero points include the provisional round while the heat grid and charts stop at `results_through`. The heat grid's aside says "through R{n}", and `SourceBadge` marks the table provisional.
4. **f1db quirks found:**
   - v2026.20.0 `season_entrant_driver` lists Ocon for rounds 1–19 although Hirakawa raced R19. We read race rows, never `rounds_text`.
   - Pit-lane `race_positions_gained` counts from the back of the grid.
   - Classified retirements carry f1db gains (BOT R15 +3), which we drop.
5. **Fixture drift:** after Las Vegas (2026-11-22) a fresh capture changes every golden.
6. The e2e uses a v2026.19.0 directory beside v2026.20.0 profile fixtures. Names resolve by id, so this is harmless.
