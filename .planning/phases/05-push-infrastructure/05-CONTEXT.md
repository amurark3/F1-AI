# Phase 5: Push Infrastructure - Context

**Gathered:** 2026-03-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Wire up APNs push notifications for live race events on physical iOS devices, with reliable device token management. This phase covers backend push dispatch, iOS token registration, and in-app notification preferences. The commentary engine and event detection from Phase 4 are already built — this phase delivers them to the user's lock screen.

</domain>

<decisions>
## Implementation Decisions

### Notification content
- Title format: Driver name + event summary (e.g., "Verstappen: Moved to P2")
- Body: Reuse the AI commentary snippet already generated by the backend commentary engine — no new text generation needed
- Tapping notification deep-links to the live timing tab
- Sound and badge: Default iOS sound + badge count increment

### Event triggering
- Events that fire pushes: overtakes (top 10 only), safety car deployments, red flags, penalties, fastest lap changes
- Overtakes scope: any driver-to-driver position change in P1–P10 (not just favorite driver)
- Sessions: all live sessions — FP1, FP2, FP3, Qualifying, Sprint Qualifying, Sprint Race, Race
- Rate limiting: Claude's Discretion — apply per-event-type cooldown windows so safety car and overtake don't suppress each other

### APNs configuration
- Auth method: Certificate-based (.p12) — no p8 key available
- Sandbox vs production detection: Claude's Discretion — use existing ENVIRONMENT env var (consistent with config.py pattern); dev=sandbox, prod=production
- APNs library: Claude's Discretion — pick best async-compatible library for FastAPI (aioapns preferred for native asyncio fit)

### Token management
- Storage: PostgreSQL — add a `device_tokens` table to a new or existing Postgres instance
- Device identity: Pair token with a device UUID sent from iOS — one row per device, upsert on re-registration
- iOS re-registers token on every foreground activation (already in roadmap requirements)
- Token cleanup: Claude's Discretion — delete token immediately when APNs returns 410 Unregistered on send attempt (standard APNs hygiene)

### Per-type opt-out
- iOS app has a settings screen with toggles for each event type: overtakes, safety car, red flags, penalties, fastest lap
- Preferences stored on-device (UserDefaults) and sent to backend at registration time alongside the device token
- Backend filters which event types to push per device based on stored preferences

### Claude's Discretion
- Rate limiting strategy per event type (window durations)
- APNs library choice
- Environment detection for sandbox/production
- Token cleanup implementation (on-failed-send vs sweep)
- PostgreSQL schema design for device_tokens + preferences

</decisions>

<specifics>

- Per-type opt-out should feel like the existing notification settings already in the app (Phase 3 added session type toggles) — extend that sheet rather than create a new one
