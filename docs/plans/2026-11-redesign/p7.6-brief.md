## 1. Goal and scope

Each finished session's weather card on the Command Center gets a **Forecast vs measured** block: OpenF1's trackside track temperature (session average, low–high), air temperature and rainfall next to the Open-Meteo figures the card already shows. A live session says its readings follow after the flag; an upcoming one stays forecast only; a finished session OpenF1 has nothing for says so.

**What exists today:** OpenF1 `weather` is already in `session_store.STORED_ENDPOINTS` and `client.get_json` reads it through the store, but the only reader is `app/data/openf1/race_context.py` (`rain_windows`, races only, for the Telemetry Lab). Nothing summarises it per session and nothing sends it to the Command Center. The forecast (`app/services/race_control/session_weather.py`, P0b.1's stored Open-Meteo series with its `as_of_label`) stays exactly as it is.

**Out of scope:** the hero's `SessionWeatherStrip`, the summary weather card (`weather` block), the risk register and the strategy baseline (all keep reading the forecast only); `build_overview` (the full, non-segment payload) and the chat weather tool; humidity, wind and pressure from OpenF1 (the forecast's wind is km/h, OpenF1's m/s: not compared in this task); any change to `session_weather.py`, `open_meteo.py` or the forecast copy beyond the footer sentence in §3.4.

## 2. The data (real OpenF1 `/weather` fields only)

OpenF1 `/weather?session_key=…` rows, about one a minute: `date`, `session_key`, `meeting_key`, `air_temperature` (°C), `track_temperature` (°C), `humidity` (%), `pressure` (mbar), `rainfall` (**0 or 1: a flag, never an amount**), `wind_direction` (°), `wind_speed` (m/s).

Each session row of `session_weather` (the `/race-control/overview/{year}/weather` segment) gains two keys:

```jsonc
"measured": {                       // null unless the session is finished and OpenF1 has readings
  "track_temp_c": 18.4,             // mean of numeric track_temperature, 1 dp; null if none
  "track_temp_min_c": 17.1,         // min, 1 dp; null if none
  "track_temp_max_c": 19.6,         // max, 1 dp; null if none
  "air_temp_c": 14.6,               // mean of numeric air_temperature, 1 dp; null if none
  "rainfall": [false, false, true]  // one per reading with a numeric rainfall, time order; true when > 0
},
"measured_note": null               // why there is no "measured"; null when there is one, and for upcoming rows
```

- Readings are the rows whose `date` parses (`parse_iso`, as `race_context.py` does) and falls inside the OpenF1 session's `date_start`..`date_end` when both are known (all rows otherwise), sorted by `date`.
- `measured` is `null` when no reading has a numeric track temperature, air temperature or rainfall.
- Notes, as module constants:
  - `NOTE_AFTER_FLAG = "OpenF1 closes its feed while a session runs; trackside readings follow once it ends."` for a `live` row, and for a `done` row whose OpenF1 session has not settled yet (`sessions.session_ended` is False: our clock's slot ended but the real session overran).
  - `NOTE_NO_READINGS = "OpenF1 has no weather readings for this session."` for a `done` row with no OpenF1 session of that code, or with an empty / readingless answer.
  - `NOTE_OFFLINE = "OpenF1 is unavailable right now."` for a `done` row when the OpenF1 call raised `OpenF1UnavailableError` (this includes `OpenF1LiveLockoutError`).

## 3. Component by component

### 3.1 Backend: `app/data/openf1/track_weather.py` (new)

- `summarise_track_weather(rows: list[dict], start: datetime | None, end: datetime | None) -> dict | None`: the `measured` dict of §2, or None. Pure; no I/O. Reuse `parse_iso` from `app.services.live_timing`; a numeric check is `isinstance(v, (int, float)) and not isinstance(v, bool)` (race_context's `_numeric` is private: don't import it).
- Module docstring: what OpenF1's station measures and that `rainfall` is a flag.

### 3.2 Backend: `app/services/race_control/measured_weather.py` (new)

- `with_measured(session_weather: dict, year: int, race: dict | None, now: datetime | None = None) -> dict`: a **new** payload (no mutation) whose `sessions` rows each carry `measured` and `measured_note`.
  - `upcoming` rows: both `None`. `live` rows: `None` + `NOTE_AFTER_FLAG`.
  - No `done` row, or no `race`/`race["round"]`: return the rows with those keys and make **no** OpenF1 call and no store read.
  - `done` rows: map `row["name"]` to a code with `sessions.session_code`. Look the code up first in the kept sessions, `session_store.weekend(year, round)` (records of `SESSION_FIELDS`; only ended sessions are kept). Only when a `done` row's code is missing there, call `weekend_sessions(client, year, round)` **once** inside one `with new_client() as client:` (it 401s during a live session: that is why the store comes first, so that during the Race the finished practice and qualifying sessions still read from the store). A session from either source that `session_ended` rejects gets `NOTE_AFTER_FLAG`.
  - Rows: `get_json(client, "weather", {"session_key": key})` (exactly that query, so it reads through the store). Then `summarise_track_weather(rows, date_start, date_end)`.
  - `OpenF1UnavailableError` from `weekend_sessions` → every unresolved `done` row gets `NOTE_OFFLINE`; from one `get_json` → that row only. Log each with structlog (`logger.warning("race_control.measured_weather.unavailable", year=…, round=…, session=…, error=str(exc))`), matching the package. Never raise.
  - Keep functions under 50 lines and the module well under the size gate.

### 3.3 Backend: `app/services/race_control/overview.py` (shared, see §8)

- In `build_overview_weather` only: `"session_weather": with_measured(sessions, year, race)`. `weather_blocks`, the `weather` card and `build_risk_register(race, sessions, …)` keep the forecast-only `sessions`. No other line changes.
