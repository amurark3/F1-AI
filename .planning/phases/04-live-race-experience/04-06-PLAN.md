# Plan: Web Live Page + Commentary Sidebar

**Phase:** 04 — Live Race Experience
**Task:** 04-06
**Requires:** 04-04

## Goal

Create the `/live` Next.js page with a `useLiveTiming` WebSocket hook, a timing tower component, and a commentary sidebar panel, then add "Live" to `NavShell`'s `NAV_ITEMS` so users can navigate to the page.

## Requirements Satisfied

- LIVE-05: Commentary panel visible in web UI as a dedicated section during live sessions

## Context

**No new dependencies.** Everything uses: `useState`, `useEffect`, `useRef` (React built-ins), Tailwind CSS (existing), Framer Motion `^12` (already installed — `AnimatePresence` + `motion.div`), `framer-motion` already in `package.json`.

**API base URL constant:** Existing pages use `API_BASE` from `frontend/app/constants/api.ts` (or similar). Check by grepping for `API_BASE` — it is already defined. Use it in `useLiveTiming` to derive the WebSocket URL: replace `https` with `wss` and `http` with `ws`.

**In-progress race detection:** The web page fetches `/api/schedule/{year}` via `fetch` on mount to find the `in_progress` race. If no in-progress race, show a placeholder. Year is the current calendar year (`new Date().getFullYear()`). The schedule response shape is the same as used by the iOS calendar: array of `{ round, name, location, status, sessions, ... }`.

**WebSocket URL pattern (matches backend):** `ws(s)://{host}/api/live/{year}/{round}` — same path as iOS uses.

**Existing CSS utilities:** `glass` and `glass-strong` are defined in `frontend/app/globals.css`. Use them for the commentary panel card style, matching existing page aesthetics.

**Layout (CONTEXT.md):** Timing tower left (flex-1), commentary sidebar right (w-80) on `lg:` screens. Mobile: stacked vertically, commentary below timing. This matches the two-column pattern used in other pages.

**Commentary entries:** Keep last 100, prepend new entries (newest first). Use `setCommentary(prev => [msg.data, ...prev].slice(0, 100))`.

**Event styling (web):** Per CONTEXT.md decision: icons and color accents per event type.
- `safety_car` → "⚠" character (text), `text-yellow-400 border-yellow-400/30`
- `position_change` → "↑↓" character (text), `text-blue-400 border-blue-400/30`
- `pit_stop` → "🔧" character (text), `text-orange-400 border-orange-400/30`
- default → "⚑" character, `text-neutral-400 border-white/10`

**`NavShell.tsx` change:** Add `{ href: '/live', label: 'Live' }` to `NAV_ITEMS` array. The live page should render even when no session is active (shows placeholder), so the nav link is always visible.

**`"use client"` directive:** Both `page.tsx` and all hooks/components in this plan require `"use client"` since they use browser APIs (WebSocket, useState, useEffect).

**`LiveTimingTower` simplicity:** The web timing tower is a simple table/list view of driver positions. It does not need to replicate the full iOS `TimingTower` fidelity — just display position number, driver number, and gap. The research confirms this is new infrastructure with no existing web equivalent.

**File `frontend/app/constants/api.ts`:** Verify this path exists. If the constant is in a different file, adjust the import in `useLiveTiming.ts`. Check with `grep -r "API_BASE" frontend/app/` during implementation.

## Implementation Steps

### Step 1: Create useLiveTiming.ts WebSocket hook

**File:** `frontend/app/hooks/useLiveTiming.ts`
**Action:** create
**Changes:**
- `"use client";` at top
- Imports: `useState`, `useEffect`, `useRef` from `"react"` and `API_BASE` from `"../constants/api"` (adjust path if the constant lives elsewhere)
- Export interfaces:
  ```typescript
  export interface LivePosition {
    position: number;
    driver: string;
    gap: string;
    last_lap: string | null;
    pit_stops: number | null;
  }
  export interface CommentaryEntry {
    id: string;
    text: string;
    event_type: string;
    timestamp: string;
  }
  export interface SessionStatus {
    status: string;
    lap?: number;
    total_laps?: number;
  }
  ```
- Export function `useLiveTiming(year: number, round: number)`:
  - State: `positions`, `sessionStatus`, `commentary`, `isConnected`
  - `useEffect` that opens `WebSocket` to `${API_BASE.replace(/^https/, "wss").replace(/^http/, "ws")}/api/live/${year}/${round}`
  - `ws.onopen`: `setIsConnected(true)`
  - `ws.onclose`: `setIsConnected(false)`
  - `ws.onmessage`: parse JSON, branch on `msg.type`:
    - `"positions"`: `setPositions(msg.data)`
    - `"session_status"`: `setSessionStatus(msg.data)`
    - `"commentary"`: `setCommentary(prev => [msg.data, ...prev].slice(0, 100))`
    - `"ping"`: ignore
  - Cleanup: `return () => ws.close()`
  - Return `{ positions, sessionStatus, commentary, isConnected }`

### Step 2: Create LiveTimingTower.tsx

**File:** `frontend/app/components/LiveTimingTower.tsx`
**Action:** create
**Changes:**
- `"use client";`, `import React from "react";`, import `LivePosition`, `SessionStatus` from `"../hooks/useLiveTiming"`
- Props: `{ positions: LivePosition[]; sessionStatus: SessionStatus | null; isConnected: boolean }`
- If `!isConnected`: render centered div with "Connecting to live timing..." and an animated pulsing dot
- If `positions.length === 0 && isConnected`: render "Waiting for timing data..." with a spinner
- Otherwise: render `<div className="overflow-x-auto">` containing a `<table className="w-full text-sm">` with:
  - `<thead>`: columns "POS", "DRIVER", "GAP"
  - `<tbody>`: `positions.map(p => <tr>` with `<td>P{p.position}</td>`, `<td className="font-mono font-bold">#{p.driver}</td>`, `<td className="text-neutral-400 font-mono">{p.gap === "LEADER" ? "—" : p.gap}</td>`
  - Leader row (position === 1) gets `className="text-white"` on the driver cell; others get `text-neutral-300`
- If `sessionStatus`: render a status pill above the table: `<span className="text-xs font-bold uppercase tracking-widest text-neutral-400">{sessionStatus.status.toUpperCase()}</span>` and if `sessionStatus.lap && sessionStatus.total_laps`: `LAP {sessionStatus.lap}/{sessionStatus.total_laps}`

### Step 4: Create the /live page

**File:** `frontend/app/live/page.tsx`
**Action:** create
**Changes:**
- `"use client";` at top
- Imports: `useState`, `useEffect` from `"react"`, `useLiveTiming` from `"../hooks/useLiveTiming"`, `LiveTimingTower` from `"../components/LiveTimingTower"`, `CommentaryPanel` from `"../components/CommentaryPanel"`, `API_BASE` from `"../constants/api"`
- State: `const [liveRound, setLiveRound] = useState<{year: number; round: number; name: string} | null>(null)`, `const [loading, setLoading] = useState(true)`
- `useEffect` on mount: fetch `/api/schedule/${new Date().getFullYear()}`, find entry where `status === "in_progress"`, set `liveRound`. If no in-progress race, `setLiveRound(null)`. Set `setLoading(false)` in finally block.
- Conditionally invoke `useLiveTiming`: since hooks can't be conditional, always call `useLiveTiming(liveRound?.year ?? 0, liveRound?.round ?? 0)` and ignore the result when `liveRound` is null (the hook will not open a WebSocket for round 0)
- If `loading`: render centered spinner
- If `!liveRound`: render placeholder:
  ```tsx
  <div className="max-w-7xl mx-auto px-4 py-16 text-center">
    <p className="text-4xl mb-4">🏁</p>
    <h1 className="text-2xl font-black uppercase italic mb-2">No Live Session</h1>
    <p className="text-neutral-400">Live timing appears here during race weekends.</p>
  </div>
  ```
- If live race active: render two-column layout:
  ```tsx
  <div className="max-w-7xl mx-auto px-4 py-6">
    <div className="mb-4">
      <h1 className="text-xl font-black uppercase italic">{liveRound.name}</h1>
      <span className="text-xs font-bold tracking-widest text-red-500 uppercase">• LIVE</span>
    </div>
    <div className="flex flex-col lg:flex-row gap-6">
      <div className="flex-1 min-w-0">
        <LiveTimingTower positions={positions} sessionStatus={sessionStatus} isConnected={isConnected} />
      </div>
      <div className="w-full lg:w-80 shrink-0">
        <CommentaryPanel entries={commentary} />
      </div>
    </div>
  </div>
  ```
