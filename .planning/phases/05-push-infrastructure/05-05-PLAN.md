@asynccontextmanager
async def lifespan(app: FastAPI):
    """Application lifespan.

    Startup order (each step depends on the prior):
      1. setup_logging()       — structured logging available before any other call
      2. init_db_engine()      — async SQLAlchemy engine + sessionmaker (Phase 5)
      3. init_apns()           — aioapns singleton; reads APNS_CERT_PATH/_B64 (Phase 5)
      4. _prefetch_race_details task — background race-detail warmup (existing)

    Shutdown order is the reverse so anything that depends on a resource
    finishes before the resource closes.
    """
    setup_logging()
    logger.info("server.starting")

    # Phase 5 — DB + APNs singletons (must succeed before serving requests).
    await init_db_engine()
    init_apns()

    # Existing background prefetch.
    task = asyncio.create_task(_prefetch_race_details())

    try:
        yield
    finally:
        # Existing prefetch teardown.
        task.cancel()
        try:
            await task
        except asyncio.CancelledError:
            pass

        # Phase 5 — graceful shutdown of APNs then DB.
        await close_apns()
        await close_db_engine()
        logger.info("server.stopped")
```

2. **Create backend/scripts/encode_apns_cert.sh** with this EXACT content. The script: (a) takes a `.p12` path as the first argument, (b) prompts for the cert password (silent input), (c) extracts both the private key and the certificate as a single PEM, (d) base64-encodes the PEM with no line wrapping, and (e) prints the base64 string. ```bash
#!/usr/bin/env bash
# Encode an APNs .p12 certificate as a base64 PEM blob suitable for the
# APNS_CERT_B64 environment variable on Render (or any other env-only host).
#
# The output is printed to stdout — pipe to `pbcopy` (macOS) or `xclip`
# (Linux) to put it on your clipboard.
#
# Usage:
#   ./backend/scripts/encode_apns_cert.sh path/to/apns.p12
#
# The script prompts for the .p12 password (input hidden).  If your .p12 has
# no password, press Enter at the prompt.
#
# Verifies the output round-trips (base64 -d | openssl x509 -text -noout) so
# you know the encoded blob is valid before you paste it.

set -euo pipefail

if [[ $# -ne 1 ]]; then
    echo "Usage: $0 <path-to-apns.p12>" >&2
    exit 1
fi

P12_PATH="$1"

if [[ ! -f "$P12_PATH" ]]; then
    echo "Error: .p12 file not found at $P12_PATH" >&2
    exit 1
fi

if ! command -v openssl >/dev/null 2>&1; then
    echo "Error: openssl is required but not installed" >&2
    exit 1
fi

# Prompt for password (hidden).
read -rsp "Enter .p12 password (press Enter if none): " P12_PASS
echo

# Convert .p12 to a single PEM containing key + cert.  -nodes leaves the key
# unencrypted in the PEM (Render-side cert is itself the secret; encrypting
# again adds operational pain without security gain in this threat model).
TMP_PEM=$(mktemp -t apns-cert.XXXXXX.pem)
trap 'rm -f "$TMP_PEM"' EXIT

if [[ -z "$P12_PASS" ]]; then
    openssl pkcs12 -in "$P12_PATH" -out "$TMP_PEM" -nodes -passin pass: 2>/dev/null
else
    openssl pkcs12 -in "$P12_PATH" -out "$TMP_PEM" -nodes -passin "pass:$P12_PASS" 2>/dev/null
fi

# Sanity-check the PEM contains both a private key and a cert.
if ! grep -q "BEGIN PRIVATE KEY\|BEGIN RSA PRIVATE KEY\|BEGIN ENCRYPTED PRIVATE KEY" "$TMP_PEM"; then
    echo "Error: extracted PEM does not contain a private key (wrong password?)" >&2
    exit 1
fi
if ! grep -q "BEGIN CERTIFICATE" "$TMP_PEM"; then
    echo "Error: extracted PEM does not contain a certificate" >&2
    exit 1
fi

# Base64 encode without line wrapping.  macOS `base64` does not support `-w0`,
# so we tr-strip newlines instead.
B64=$(base64 < "$TMP_PEM" | tr -d '\n')

# Round-trip verification: decode, parse, ensure the cert is parseable.
if ! echo "$B64" | base64 -d | openssl x509 -text -noout >/dev/null 2>&1; then
    echo "Warning: round-trip verification failed (cert may still work, but inspect manually)" >&2
fi

echo "$B64"
echo >&2
echo "Done.  Length: ${#B64} chars." >&2
echo "Paste the value above into the APNS_CERT_B64 env var in the Render dashboard." >&2
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Render dashboard env vars → backend process | Secrets cross from Render's encrypted store into the running container; never logged |
| .p12 file (user filesystem) → encode_apns_cert.sh → base64 → Render env var | Cert never leaves the user's machine in plaintext form except as the b64-encoded blob the user pastes; .p12 is .gitignored (Plan 01) |
| Postgres connection string (DATABASE_URL) → backend lifespan | Render's `fromDatabase` injection is over the internal Render network; uses TLS at the Postgres protocol layer |
| backend lifespan() → APNs HTTPS to api.push.apple.com | TLS-pinned by aioapns; client cert is the auth credential |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Information Disclosure | encode_apns_cert.sh leaving .p12 password in shell history | mitigate | Script uses `read -rsp` (silent input, not echoed); the password is never written to a file or env var. Users who pipe a password via `echo "pw" \| ./script.sh` should be warned in the runbook |
| T-05-05-02 | Information Disclosure | base64 cert blob in CI build logs | mitigate | Render's env var values are never echoed in build logs unless the buildCommand explicitly prints them; our buildCommand (`pip install ... && alembic ... && python ...`) never references APNS_CERT_B64; cert leakage requires custom build modification |
| T-05-05-03 | Information Disclosure | DATABASE_URL with embedded password in process env | accept | Render's standard pattern; the URL is visible to any process inside the container but the container itself is isolated. ASVS V14 acceptable for portfolio scope |
| T-05-05-04 | Information Disclosure | apns_client logging APNS_CERT_B64 contents on decode failure | mitigate | Plan 02's apns_client._materialize_cert logs only the exception type/message via structlog, never the b64 blob (Plan 02's threat T-05-02-04) |
| T-05-05-05 | Denial of Service | alembic upgrade head failing during build blocks deploys | accept | Migration failures should block deploy — that is the desired behavior (catches schema drift before serving traffic). Recovery is rolling back the offending migration commit |
| T-05-05-06 | Tampering | render.yaml committed with secrets | mitigate | render.yaml uses `sync: false` for every secret; only non-secret values (`APNS_BUNDLE_ID=com.f1ai.app`, `ENVIRONMENT=production`) are inline. The repo never carries APNs cert material |
| T-05-05-07 | Information Disclosure | .env file accidentally committed | mitigate | .gitignore (Plan 01) covers `*.p12`, `*.pem`, `*.p8`, `secrets/` — but does NOT explicitly cover `.env`. The base .gitignore in Python projects typically does (cookiecutter pattern); Task 3 verifies `.env.example` is NOT ignored, which implies `.env` is. If not, add `.env` to .gitignore as part of this task |
| T-05-05-08 | Spoofing | Anyone with Render dashboard access can swap APNs cert | accept | Render dashboard access is gated by the user's account; out of scope for portfolio threat model |
| T-05-05-09 | Information Disclosure | DEPLOY-NOTES.md leaking real cert paths or URLs | mitigate | All paths in the runbook are placeholders (`/path/to/your/apns.p12`); URLs are example domains. No production secrets embedded in committed docs |
