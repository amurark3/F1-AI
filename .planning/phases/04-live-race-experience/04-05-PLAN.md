# Plan: iOS Commentary UI

**Phase:** 04 — Live Race Experience
**Task:** 04-05
**Requires:** 04-04

## Goal

Add `CommentaryEntry` model and WebSocket handling to the iOS data layer, then build a scrollable `CommentaryFeedView` with event-type icons and a segmented "Timing" | "Commentary" picker in `LiveTab` with a badge dot that appears when new commentary arrives while the user is on the Timing segment.

## Requirements Satisfied

- LIVE-03: AI commentary generates contextual insights on significant timing events (iOS display)
- LIVE-05: Commentary panel visible in iOS UI as a dedicated section during live sessions

## Context

**Three files to modify, one to create:**
- `ios/F1AI/Models/LiveTiming.swift` — add `CommentaryEntry` struct and `.commentary` case to `LiveTimingData`
- `ios/F1AI/Services/LiveTimingService.swift` — handle new `"commentary"` message type in `handleMessage()`
- `ios/F1AI/ViewModels/LiveTimingViewModel.swift` — add `commentaryEntries: [CommentaryEntry]` array
- `ios/F1AI/Views/Live/CommentaryFeedView.swift` — new file

**LiveTimingData decoder problem:** The existing `LiveTimingData` enum uses a `singleValueContainer` that tries to decode as `[LivePosition]`, `SessionStatus`, or `FlagEvent` in order. A `CommentaryEntry` cannot be distinguished this way because the parent `LiveTimingMessage` wraps `{"type": "...", "data": {...}}`. The `"commentary"` type must be handled at the `LiveTimingService.handleMessage` level by branching on `decoded.type` BEFORE attempting `LiveTimingData` decoding. This avoids changing the brittle enum decoder.

**Revised decoding approach:** In `handleMessage()`, after decoding the raw JSON, check `msg["type"] as? String`. If it equals `"commentary"`, decode `msg["data"]` as `CommentaryEntry` directly and update `LiveTimingService.commentaryEntries`. Do NOT route it through `LiveTimingData`.

**Existing `handleMessage()` flow:** Decodes `LiveTimingMessage` — but since `LiveTimingData` will throw for an unknown `data` shape, the current code silently drops unrecognized messages (`guard let decoded = try? ...`). Handle `"commentary"` BEFORE the `LiveTimingMessage` decode attempt, using a two-step decode: first decode as `[String: Any]` to read `type`, then branch.

**`LiveTimingService` must publish `commentaryEntries`:** Add `var commentaryEntries: [CommentaryEntry] = []` as a stored property. `LiveTimingViewModel` exposes it as a computed property same as `positions`.

**Commentary feed behavior (CONTEXT.md):** Scrollable session history — all entries preserved. New entries prepended (most recent at top). Badge dot on Commentary segment when new entries arrive while user is on Timing segment. No auto-switch segments. No haptic/sound — visual only.

**Event type icons (CONTEXT.md):** red for safety car, yellow for pit stop, blue for position change. Use SF Symbols:
- `"safety_car"` → `"exclamationmark.triangle.fill"`, `.red`
- `"position_change"` → `"arrow.up.arrow.down"`, `.blue`
- `"pit_stop"` → `"wrench.and.screwdriver.fill"`, `.orange`
- default → `"flag.fill"`, `.gray`

**Framer Motion equivalent in SwiftUI:** Use `.animation(.easeInOut, value: entries.count)` on the `ScrollView` content, or wrap `ForEach` in a simple `LazyVStack` — no custom animation needed.

### Step 2: Handle "commentary" message type in LiveTimingService

**File:** `ios/F1AI/Services/LiveTimingService.swift`
**Action:** modify
**Changes:**
- Add `var commentaryEntries: [CommentaryEntry] = []` as a stored `@Observable` property on `LiveTimingService`
- In `handleMessage(_ message:)`, replace the current single-step decode with a two-step decode:
  ```swift
  private func handleMessage(_ message: URLSessionWebSocketTask.Message) {
      let data: Data
      switch message {
      case .string(let text): data = Data(text.utf8)
      case .data(let d): data = d
      @unknown default: return
      }

      // Step 1: Decode type field only
      guard let raw = try? JSONSerialization.jsonObject(with: data) as? [String: Any],
            let type = raw["type"] as? String else { return }

      // Step 2: Branch on type
      if type == "commentary" {
          guard let dataObj = raw["data"],
                let dataData = try? JSONSerialization.data(withJSONObject: dataObj),
                let entry = try? JSONDecoder().decode(CommentaryEntry.self, from: dataData)
          else { return }
          Task { @MainActor in
              // Prepend new entry (most recent first), keep up to 100
              self.commentaryEntries = ([entry] + self.commentaryEntries).prefix(100).map { $0 }
          }
          return
      }

      // Existing path: decode as LiveTimingMessage for positions/sessionStatus/flag
      guard let decoded = try? JSONDecoder().decode(LiveTimingMessage.self, from: data) else { return }
      Task { @MainActor in
          switch decoded.data {
          case .positions(let pos): self.positions = pos
          case .sessionStatus(let status): self.sessionStatus = status
          case .flag(let flag): self.lastFlag = flag
          }
      }
  }
  ```
