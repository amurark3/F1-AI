# Decisions: the November 2026 redesign, data platform and hardening

The project ran from 2026-11-02 to 2026-11-23 and covered three plans: accuracy fixes and the site-wide redesign, moving data reads off FastF1, and backend hardening after an audit. This file records what was decided, why, and where the history lives. The plans, task briefs and HTML mockups were deleted once the work shipped. Read them in git at commit `9a814aa`:

- `git show 9a814aa:docs/plans/2026-11-redesign/PLAN.md` (the plan), `STATUS-archive.md` + `STATUS.md` (the day-by-day log with evidence), `*-brief.md` (task briefs), `fastf1-inventory.md`.
- `git show 9a814aa:docs/plans/2026-11-hardening/PLAN.md` (the audit fixes H1–H12).
- `git show 9a814aa:docs/design/redesign/<page>.html` (the mockups; `index.html` lists them, `system.css` holds the tokens, `grand-prix-tabs.md` the hub spec).

The Oracle hosting move is not done and is deferred: see [`plans/oracle-deferred/PLAN.md`](plans/oracle-deferred/PLAN.md).

## Why it started

On 2 Nov 2026, the morning after the Mexico City GP (R19), no single API had the result right. FIA document 86 (Final Race Classification) applied post-race penalties: Piastri 7→13, Colapinto 8→15, Gasly 10→17. OpenF1 `session_result` matched it, Jolpica still showed the pre-penalty order, and OpenF1 `championship_teams` had Red Bull on 380 instead of 382. Mexico also had a red flag after lap 45, and Jolpica listed the suspension tyre changes as pit stops (around 38 min). The rule became: **F1 is about accuracy**. The plan fixed the data bugs first, then redesigned every page.

## Data and accuracy

Provisional results turn confirmed when it lands (D2.3).                                                                                                                                                                                                                        | It is the only source that carries post-race penalties correctly. | **Race Rewind labels "position changes"** unless a change is a classified pass (P8).                                                                                                                                                                                                                                                                                | F1 publishes no overtake feed.                                                                                                                                  |

## Grand Prix hub (decided in P4.3a, signed off 2026-11-14)

1. Tabs: Weekend · Sessions · Grid · Results · Stints · Predictions. **Every round opens on Weekend**, and picking another round clears the tab (user, 2026-11-18; replaced "a finished race opens on Results").
2. Results has no Grid or places-gained column: the Grid tab and the Debrief's grid→finish chart own movement.
3. Results has no Laps column: finishers read `+1 lap`, non-finishers carry laps in the reason (`Collision · 58 laps`).
4. The qualifying gap is measured within the driver's own part (the official figure).
5. A DNF in the prediction Review reads `DNF` · reason with no place delta, and is scored only as a retirement call.
6. "Confidence 60–75 %" became **"Agreement 60–75"** with no % sign, because it is the spread of the model's inputs, not a probability.
7. The Order view drops Pts, Win, Podium, DNF and Crash estimates (other views own them); "vs grid" shows only after qualifying.
8. A pit-lane start counts from the back of the grid for places gained, and reads "from the pit lane", never "from P22".
9. The sprint lives in Results (classification) and Grid (its grid).

The hub's race hero heads every tab (user, 2026-11-18: a Weekend-only hero was confusing). The selected round's tick is never red, because red read as Ferrari.

## Rulebook and memory search without local models (Phase S, user 2026-11-22)

- **Rulebook:** hybrid search, Postgres full-text plus Gemini `gemini-embedding-001` at 768 dimensions; full-text alone when Gemini fails or hits its quota. Why: Render's 512 MB means `ENABLE_LOCAL_MODELS=false`, so the torch embedder and reranker can't load.
- **Chat memory:** full-text search only. Private chat text is never sent to Google: the free tier may use it to improve products, and each turn would cost about 3 calls.
- Not `text-embedding-004`: Google shut it down on 2026-01-14.

## Testing

- **Frontend coverage is literal 100 % per file across `app/**`** (P1, P9), with no coverage-ignore comments: dead code is deleted instead. Config files (`next.config.ts`, `instrumentation*`, `sentry.*`) stay outside the gate (user, 2026-11-16), because they hold no behaviour a test can prove.
- **No coverage for code a later phase rewrites or removes** (user, 2026-11-03); the replacing task covers it.
- **Tests use real captured rows** (OpenF1, f1db, Jolpica, FIA PDFs) under `tests/fixtures/`.
- **Node 22** in CI and locally (P1.10), because Node 20 is end of life.

## Backend hardening (H1–H12, from the 2026-11-23 audit; PR #113)

The load assumed: one free Render instance (512 MB, one process), a few visitors at a time, race-weekend spikes, and an API anyone can call.

| Decision                                                                                                                                                                                                                                                                                                     | Why                                                                                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| **Only `POST .../compute` with `X-Admin-Key` runs the model** (H1); every other path reads the store and shows "no prediction yet".                                                                                                                                                                          | The overview, the legacy route and a chat tool all ran and stored the model on a cache miss.                                        |
| **Chat memory needs a real per-browser id**; with none, no recall and no saving. The unused memory HTTP routes are deleted (H2).                                                                                                                                                                             | —                                                                                                                                   |
| **Chat input limits and a per-IP rate limit** (H4), in memory, keyed on Cloudflare's client-IP headers, not `X-Forwarded-For`. A shortcut: move to a shared store if the backend ever runs more than one process.                                                                                            | Bounds abuse of the free LLM quota.                                                                                                 |
| **One OpenF1 poll per live session**, shared by every socket (H5).                                                                                                                                                                                                                                           | Each socket polled OpenF1 three times per interval on its own.                                                                      |
| **One single-flight helper** (`app/api/single_flight.py`) for prediction compute and chat tools (H6, H7).                                                                                                                                                                                                    | A timed-out run kept going, and a retry started a second one beside it.                                                             |
| **Memory and tool output are quoted data, never system instructions; no raw exception text reaches the model** (H10–H12).                                                                                                                                                                                    | A stored message ("ignore the F1-only rule") came back inside the system prompt; Postgres and HTTP errors can carry hosts and URLs. |
| **The deprecated iOS app is deleted** (H9). iOS was out of scope from 2026-11-02; git history keeps it.                                                                                                                                                                                                      | Web-only development.                                                                                                               |
| **Accepted, not fixed:** two tiny caches that grow forever; forged assistant turns in `POST /api/chat` (every tool is read-only, SQL runs on a read-only connection, the rate limit bounds the cost); the memory id acts as a bearer key (random UUIDs). The real fix for the last two is server-issued ids. | Low impact at this load.                                                                                                            |
